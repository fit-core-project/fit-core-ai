# 루틴 코어 이식 브랜치

## 범위

- 협업 기준: `origin/develop`의 `80e4cbebc6d6ae9eb79b2d58263f2e1adacb5699`.
- 이식 출처: 별도 로컬 core-snapshot `c488834c17ba4e1601175292ca8a5b31aceca8a2`, 마지막 추천 로직 변경 `e0d04e7`. 이 해시들은 이 저장소의 조상이 아니며, 전체 스냅샷 이력을 합치지 않았다.
- 루틴 후보 조회/랭킹/필터, 결정론적 처방, 프롬프트/선택 검증, fallback, v4 코어 경계, 검수된 ID 연결표와 카탈로그를 이식한다.
- 식단·영양제·quicklog 구현/데이터, 배포 설정, requirements, `main.py`는 최신 develop을 유지한다. 공용 LLM의 reasoning 기본값 변경은 routine에만 한정한다.

## 아직 배포 완료가 아님

**기존 legacy HTTP 엔드포인트는 제약 프로필 조회 실패와 행 없음을 구분하지 못할 수 있다(D1 미구현).** 이 브랜치는 코어 함수와 테스트를 제공하며 v4 HTTP 연결, BE/FE DTO·저장·화면 및 BE fallback 통합을 완료한 것이 아니다. develop에 병합하거나 운영에 배포하기 전에 아래 전달 명세를 구현해야 한다.

1. [전달 패키지](handoff/developer-handoff-v1.1-2026-10-16/README.md).
2. [v4 계약](handoff/developer-handoff-v1.1-2026-10-16/03-contract-v4.md).
3. [legacy 필수 연결 범위](handoff/developer-handoff-v1.1-2026-10-16/07-legacy-implementation-scope.md).

패키지는 2026-10-16에 잠근 원본이다. 그 안의 runtime commit/asset hash는 **이식 전 기준**이며 현재 브랜치와 동일하다고 간주하지 않는다. 이식 차이와 새 검증은 이 문서 및 새 검증 manifest로 구분한다. 기존 활성 계약과 golden은 덮어쓰지 않는다.

## 데이터

`fit_core.sqlite`는 24,653개 운동의 로컬 참조 카탈로그이며 사용자 운영 DB가 아니다. 원본 SHA-256은 `cf0d651dbb5c6e961289467a2d4e23520cafd083f24ca0a77554bdd003cebe81`. 약 61.4 MiB이므로 GitHub의 50 MiB 권고 크기를 넘는다(100 MiB 파일 제한 미만). 배포 방식/LFS 전환은 별도 협업 결정이며 이번에 도입하지 않았다.

사용자 형태 테이블의 3행은 `scripts/build_constraints_db.py`가 생성한 QA 합성 프로필이다. 실사용자 데이터가 아니다. 이 카탈로그를 사용자 프로필 저장소로 공유하지 않는다. 운영 사용자 제약의 조회·인증·실패 처리는 BE/AI adapter 계약을 따라야 한다.

빌더는 카탈로그를 재작성하므로 서버 시작 시 자동 실행하지 않는다. 검증은 제공된 카탈로그를 읽기 전용으로 사용한다. 카탈로그 연결 승인과 운동 추천 허용은 별개이며, 승인 11쌍이 모든 운동의 자동 연결 또는 추천 승인을 뜻하지 않는다.

원천 자료의 라이선스 검수 상태는 보존하며, 이번 이식이 별도의 이용허락이나 임상 안전성 인증을 부여하지 않는다. 외부 이미지·영상·설명문 원문은 포함하지 않는다. 세부 admission JSON에 기록된 과거 근거 문서 경로/해시는 보관 이력을 가리키며, 모든 과거 조사 기록이 이 브랜치에 포함된 것은 아니다. 포함된 ID 검수 문서의 과거 권고와 현재 승인은 구분하며 현재 상태는 `engines/data/catalog_identity_bridge_v1.json`을 따른다.

## 유지된 한계

2026-10-16 승인된 품질 한계 11개: 둔근 단독 50/60분의 초·중·상급 6개, 051~054 시간 활용 부족 4개, 025 제한된 삼두 요청 1개. 예상 시간이 요청의 절반 미만이면 v4 짧은 루틴 안내를 제공한다. 시간을 채우려고 금지 동작·중복 세트·미요청 부위를 자동 추가하지 않는다.

원문 피드백 38건은 해결22/부분해결15/한계수용1이었다. 코어 인수 완료는 임상 안전성, 모든 입력 조합의 품질, 웹 통합 완료를 뜻하지 않는다. 이전 실모델 증거는 300평가와 수정 영향 범위15평가이며, 마지막 소스에서 315건을 전부 다시 실행했다는 뜻이 아니다.

## 이식 충돌 정리

| 영역 | 처리 |
|---|---|
| 식단/영양제/quicklog | develop 보존. routine reasoning 기본값만 분리 |
| HTTP/배포/의존성 | develop 보존, 새 공개 경로 자동 연결 없음 |
| 개인 경로 | 카탈로그 상대 경로 사용, Windows Ollama 탐지는 명시적 환경변수로만 |
| BE 숫자 ID 검사 | 동일 BE 커밋의 5개 소스 fixture와 SHA-256을 저장해 옆 폴더 의존 제거 |
| 부상 severity 테스트 | 승인된 이진 부상 입력으로 변경, telemetry 검사 의도 유지 |
| 구 prompt/평가/golden | 원본 보존, 승인 코어 fixture를 새 버전 이름으로 추가 |
| 로그 보안 검사 | develop의 LogRecord 기반 검사 유지 |

검증 결과는 [이식 검증 보고서](reviews/routine-core-migration-validation-v1-2026-10-19.md)를 따른다. 합성 재생/강제 장애는 실제 모델 호출 성능으로 계산하지 않는다. 보존된 골든 1건과 BE DTO 경계 4건의 실패가 있으므로 전체 테스트 통과 또는 운영 준비 완료로 해석하지 않는다.
