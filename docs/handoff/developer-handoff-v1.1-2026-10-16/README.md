# 운동 루틴 AI 코어 연결 패키지 v1.1

2026-10-16 / 코어 기준 `e0d04e7952cb8e63c36e727f51abe29d17d400f7` / **D1~D7 권장안 사용자 승인 반영**.
코어 인수와 연결 정책 결정은 완료됐다. 이 폴더는 BE/FE 구현 완료나 배포 승인이 아니다. 확정 정책은 [결정 기록](06-decisions.md), 남은 구현은 요청서와 검증표를 따른다. v1 원본은 보존한다.

## 개발자가 먼저 할 일

1. BE01: v4 DTO와 시간·거리·그룹 필드의 저장/조회 왕복부터 확인한다.
2. BE02: 숫자 ID를 보존하고 승인 연결·admission·역변환을 모두 검증한 제공 범위를 manifest로 고정한다(D6).
3. BE04: 조회 실패와 제약 없음의 구분을 연결한다. 한국어 안내 문구로 오류를 분류하지 않는다.
4. BE05: BE fallback에 BF01~20 제약 검사를 적용한다.
5. FE01·FE04: 처방 단위와 요청/예상시간·짧은 루틴 안내를 표시한다.

정책은 확정됐다. 위 번호는 아래 요청서의 완료 확인 항목과 연결되며, 실제 서비스 적용 전 통합 검증은 별도로 필요하다.

## 범위와 책임

코어는 후보 조회/필터/순위, 모델 선택, 결정론적 처방·시간·그룹, 검증·fallback, JSON 경계를 제공한다. BE는 인증·프로필/이력 공급·버전 라우팅·DTO·영속 저장·장애 경로, FE는 선택 입력·설명·처방 표시·실행/재조회 흐름을 연결한다. 식단·영양제·새 요가/재활 엔진은 범위 밖이다.

코어 소스는 **AI 서버 저장소에 이관할 위 커밋 기준**으로 별도 제공한다. 이 SHA가 현재 협업 원격에 있다는 뜻은 아니다. 소스 제공자에게 해당 커밋 또는 대응 이관 커밋을 받고 `asset-provenance.json`의 파일 해시를 대조한다. 소스 미확보 시 다른 최신 소스로 검증을 대체하지 않는다. ZIP에는 코어 소스·DB·개인 환경변수·접속 정보가 없다. 코어 회귀에는 해당 소스·동일 DB와 Python 의존성이 필요하다. 전송 자체 검사는 Python 표준 라이브러리만 사용한다.

## 중요한 연결 제한

- **알려진 공백:** adapter 적용 전 기존 legacy loader는 제약 조회 오류와 행 없음을 구분하지 못할 수 있다(D1 미구현). [필수 구현 범위](07-legacy-implementation-scope.md)를 완료하기 전 구 경로를 새 코어와 동등한 보호 경로로 취급하지 않는다.
- 실제 envelope 문자열은 `routine-core-v4-draft-v3`다. 문서 개정 v4와 wire 버전을 혼동하지 않는다.
- 숫자 운동 ID를 V24ROW로 대체 저장하지 않는다. 연결 승인 11쌍과 전체 운동 DB를 구분한다.
- 미지원 확장값을 잘라내거나 fallback에서 제약을 낮춰 성공으로 만들지 않는다.
- 짧은 루틴은 그대로 알리고, 목표 부위 확장은 사용자가 확인한 새 요청으로만 진행한다.
- 11개 품질 한계는 수용됐으나 부족 지표는 남아 있다. 둔근 단독 17~21분, 025 12분, 051~054 34~37분이 대표 관찰이다. 시간 보장·부상 예방 보장을 표시하지 않는다.
- 협업 기준 SHA는 2026-10-06 조사 시점이다. 현재 원격 최신 버전으로 간주하지 않는다.

`schemas/`의 요청·응답 3종은 현 모델에서 추출했다. `external-error.schema.json`만 승인된 신규 HTTP 구현 목표이며 현 서버 구현 증거가 아니다. `fixtures/`는 합성 전송/경계 자료이며 추천/의료 검수 승인이 아니다. 이전 초안은 `references/prior-drafts.md`의 원본 링크로 보존한다. 현재 계약은 `03-contract-v4.md` 한 개로 읽는다.
