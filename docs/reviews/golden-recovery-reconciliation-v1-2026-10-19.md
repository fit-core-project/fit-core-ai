# 회복 분량 골든 정합화 v1

## 결론과 범위

기준 커밋은 `cec77a2840d431dc94850ad08eb243815111d881`이다. 기존 골든의 20분/복합 운동당 2세트는 회복 분량 정책 v2 이전 기대값이다. 현재 코어의 26분/복합 운동당 3세트는 이미 적용된 역할·숙련도별 상한 정책과 일치한다. 이번 작업은 추천 로직, DB, 프롬프트, 계약 변경이 아니라 테스트 기대값 정합화다.

`tests/golden/main_path_with_deterministic_v4.json`은 현재 출력 녹화가 아닌 아래 정책과 산식으로 수동 구성했다. 기존 v1~v3은 바이트 단위 보존한다. `test_golden_baseline.py`의 전체 출력 투영 동등성 검사를 유지하고 기준 파일만 v4로 바꾼다.

## 정책 근거와 독립 계산

- `engines/prescription/adjustments.py`: 정책 식별자 `routine-recovery-dose-v2-2026-09-17`; 역할·숙련도 상한의 최솟값을 기준으로 DOMS1 세트 상한과 RIR 하한을 적용한다.
- `engines/prescription/experience.py`: 이 사례의 중급 근비대 복합 운동 상한 4, 고립 운동 상한 3.
- `engines/prescription/estimator.py`: 준비 300초, 종목 간 전환 120초, 복합 수행 60초/세트, 고립 수행 40초/세트. 마지막 세트 뒤 휴식은 중복 가산하지 않는다.
- 보관된 2026-09-17 회복 분량 정책 v2 문서·검토 보고서·변경 전 소스와 대조했다. 변경 전은 근비대 공통 기준 3에 DOMS1 비율을 적용했고, 이후는 역할·숙련도 상한을 사용한다. 과거 조사 자료 전체가 이 저장소에 포함된 것은 아니다.

동일 입력: 중급, 근비대, 밀기, 가슴 DOMS1, 보통 컨디션, 요청 60분.

| 항목 | 이전 골든 v3 | 현 정책 골든 v4 |
|---|---:|---:|
| 벤치프레스 / 푸시업 / 플라이 세트 | 2 / 2 / 2 | 3 / 3 / 2 |
| RIR | 3 / 3 / 3 | 3 / 3 / 3 |
| 세트 간 휴식(초) | 120 / 120 / 75 | 120 / 120 / 75 |
| 합산 시간(초) | 1175 | 1535 |
| 올림 표시(분) | 20 | 26 |

DOMS1 상한은 복합 `round(4 * 0.8) = 3`, 고립 `round(3 * 0.8) = 2`다. 이미 세트가 더 적으면 늘리지 않는다.

```text
이전: 300 + 2*120 + 2*(2*60 + 120) + 2*40 + 75 = 1175초
현재: 300 + 2*120 + 2*(3*60 + 2*120) + 2*40 + 75 = 1535초
차이: 2*(60 + 120) = 360초
```

허용한 차이는 앞 두 블록의 처방 1세트씩 추가, 총 예상 시간, 그 시간에 대응하는 요약 문장뿐이다. 운동 종류·순서·반복·RIR·휴식·그룹·점수 근거·경고는 동일하다. 비율과 RIR 기준은 버전 관리된 제품 정책이며, 이 검증이 임상적 정확성이나 개인의 부상 안전성을 증명하지는 않는다.

## 검증 방법

새 `tests/test_golden_recovery_policy_v4.py`는 다음을 검사한다.

- 역사 골든 3개 SHA-256 보존.
- v3에서 허용한 차이만으로 독립 구성한 v4와 파일의 전체 동등성.
- 세트 부족/초과, RIR 저하, 휴식 변경, 시간 회귀, 점수 근거 변경의 6개 변조를 거부.
- 직접 DOMS1/2 처방, 이미 줄어든 세트를 복구하지 않는 동작, 휴식·반복 보존.
- 1175초/1535초 독립 산술과 실제 시간 추정 함수의 동등성.

재실행 대상:

```sh
python scripts/verify_core_migration.py collaboration --out .artifacts/golden-collaboration
PYTHONPATH=.:tests PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -p no:cacheprovider -p stage2_offline_guard tests/test_golden_baseline.py tests/test_golden_recovery_policy_v4.py tests/test_feedback_recovery_completion.py tests/test_low_readiness_fill.py
```

실행은 네트워크 차단, 카탈로그 읽기 전용, dotenv 비활성화 환경에서 수행했다. 상세 최종 집계는 [증거 요약](../evidence/golden-recovery-reconciliation-v1-2026-10-19/summary.json)에 기록한다. 처음 작성한 테스트 7건은 필수 `exercise_rationale` 입력 누락으로 실패했고, 테스트 입력만 보완했다. 실패 기록은 내부 증거에 보존한다.

| 이번 실행 | 통과 | 실패 | 건너뜀 |
|---|---:|---:|---:|
| 골든·회복·컨디션 집중 검증 | 95 | 0 | 0 |
| 협업 회귀 | 835 | 0 | 19 |

두 집합은 일부 중복되므로 합산한 값을 고유 테스트 수로 제시하지 않는다. 협업 회귀의 건너뜀은 식단 및 영양제의 선택 실행 항목이며 통과로 계산하지 않는다. 독립 검토에서도 정책·산술 일치와 전체 동등성 assertion 보존을 확인했다.

## 증거의 범위와 남은 작업

이번 변경의 runtime·데이터 바이트가 기준 커밋과 동일한지 확인한다. 기존 코어 4,128건 통과, 재생 81건, 강제 장애 81건은 [이식 검증 보고서](routine-core-migration-validation-v1-2026-10-19.md)의 이전 실행 증거다. 이번에 다시 실행했다고 주장하지 않는다. 이전 보고서와 manifest는 당시 커밋의 기록으로 보존한다.

새 실모델 호출, 새 의존성 환경 설치, BE/FE E2E는 수행하지 않는다. BE 숫자 ID 계약 경계 F02~F05와 legacy HTTP D1 연결 작업은 이번 정합화로 해결되지 않는다. 따라서 웹 통합 또는 전체 배포 준비 완료를 의미하지 않는다.
