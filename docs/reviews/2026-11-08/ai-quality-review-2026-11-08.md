# fit-core AI 품질 실측 리뷰 (2026-11-08)

로컬 AI 서버(gemma4:latest, Ollama, 127.0.0.1:8000)에 실제 요청을 보내 측정했다. 모킹된 단위 테스트(941개 통과)는 출력 품질을 말해주지 않으므로 여기 수치에 넣지 않았다.

## 1. 루틴 생성

### 지키는 것
- 통증 부위, 사용 불가 장비, 근육통 3단계 부위, 시간 상한을 20회 모두 지켰다.
- `setIndex` 1부터 연속, 운동명 한글, 설명문에 영문 코드 노출 없음.

### 문제 (실측 근거)
1. **부위를 직접 골라 만들면 빈 루틴** (버그, 영향 큼)
   - FE가 부위를 고르면 `targetSplitLabel: "custom"`을 보내는데(`fit-core-frontend/app/ai_routine/generator/page.tsx:180`), AI의 분할 표(`engines/registry.py:71`)에 `custom`이 없어 대상 근육이 `[]`가 된다. `targetMuscles`는 무시된다(`engines/routine_pipeline.py:420`).
   - 실측: `custom` + 이두·삼두 45분 → `failed / emptyCandidate`. 같은 부위를 분할 없이 보내면 정상 생성.
2. **중량이 비현실적** (영향 큼)
   - 밀기: 스미스 벤치·인클라인·덤벨 프레스·케이블 프레스 6종이 전부 80kg × 5. 덤벨 80kg은 불가능한 처방.
   - 당기기: 덤벨 로우 100kg, 랫풀다운 100kg(씰 로우 120kg 기록에서 차용). 하체: 고블릿 스쿼트 87.5kg.
   - 원인: 같은 근육의 다른 운동 기록이나 빅4 1RM을 장비(덤벨은 한 손 기준)·동작 차이 보정 없이 복사(`engines/prescription/weight.py:159-170`). 차용 단계가 사용자 본인 기준 중량보다 먼저 실행된다.
   - 1RM × 목표 강도 고정 비율이라, 최근 100kg×8을 한 사람에게 90kg×8이 나오는 등 점진적 과부하가 거꾸로 갈 수 있다(`weight.py:151-157`). RPE는 받기만 하고 안 쓴다.
3. **운동 구성이 한쪽으로 쏠림**
   - 밀기 루틴 4건(신규 사용자 포함) 모두 가슴 운동 6개, 삼두·어깨 0개. 당기기는 등 3개, 이두 0개.
   - 세트 수가 4·3·2·2·1·1로 줄어드는 패턴. 1세트짜리 운동이 반복적으로 생긴다.
4. **같은 운동 중복**: 하체 2건에서 `라잉 레그 컬`이 두 번 들어갔다. 중복 exerciseId 검사가 없다(`engines/llm_parser.py:695`).
5. **프로필 통증이 필터에 안 쓰임**
   - 데모 사용자 프로필에 허리 통증이 있는데 코어 루틴 1순위가 컨벤셔널 데드리프트, 폴백 코어 루틴은 데드리프트 120kg + 굿모닝. 프로필 `pain_areas`와 `user_note`는 프롬프트 텍스트로만 들어가고 후보 필터에는 안 들어간다.
6. **피곤한 날 짧은 코어 루틴이 매번 폴백**
   - 코어 20분 + 컨디션 낮음 → 2/2회 폴백. 실제 원인은 세트 예산 초과(`set budget overflow`)인데 사유 코드는 `schemaError`, 화면 문구는 "AI 코치 연결이 원활하지 않아"라 사용자에게 잘못 설명된다.
7. **시간을 너무 적게 씀**: 어깨 통증 + 가슴 근육통 2 + 70분 → 삼두 운동 3개 17분. 근육통 2(중간)에 가슴을 통째로 빼고 남은 시간을 채우지 않는다.
8. **신규 사용자 중량 전부 비어 있음**: 기록이 없으면 중량 null. 첫 세트 가이드(예: "편하게 12회 가능한 무게")가 없다.
9. **설명이 일반론**: 근거 문장이 "복합 운동을 먼저 배치…" 수준이고 최근 기록·수치를 인용하지 않는다. LLM이 설명을 쓴 뒤 서버가 세트·중량을 바꾸기 때문에 설명이 최종 숫자와 연결될 수 없다. 경고는 거의 매번 "컨디션에 맞춰 중량과 반복 수를 조절하세요" 한 줄.
10. **장비 필터가 과하게 엄격**: 장비 목록 "BARBELL, DUMBBELL"은 대안 목록인데 하나만 막혀도 운동을 뺀다(`engines/db_queries.py:221`, 174개 중 48개가 다중 장비).

## 2. 식단 기록 (`/parse-diet`)

- 기존 20건: REAL 15/20(이전 기록 15/20, 그 전 16/20, 큰 회귀 아님). 음식 인식 100%, 양 90%, **칼로리 허용오차 이내 50%**, 매크로 60%. 응답 1.3~2.3초.
- 추가 12건 오류:

| 입력 | 결과 | 원인 |
|---|---|---|
| 치킨 두 조각이랑 콜라 한 캔 | 1500kcal, 콜라 단백질 24.8g | "콜라"가 DB의 **"쇼콜라 케이크"**에 부분 문자열 매칭(`engines/food/food_reranker.py:85-88`). 치킨은 "햄버거 치킨"에 매칭 |
| 라면 하나 끓여 먹음 | 124kcal (실제 약 500) | "개" 단위를 모르면 100g으로 계산(`engines/food/food_engine.py:309-318`) |
| 아침: 계란 2개, 바나나 1개, 아메리카노 | 계란이 200g으로 계산 | 개당 무게 표가 일부 음식에만 있음 |
| 오늘 너무 피곤했다 그래도 저녁엔 샐러드 먹음 | 항목 0개 | 잡담이 섞이면 음식 추출 실패 |

- 그 밖에(코드): 조각·캔 단위 표 없음, 단위 비면 g로 간주("계란 2" → 2g), 프롬프트 예시가 200g에 100g당 단백질을 적어 LLM이 1인분을 절반으로 적을 수 있음(`engines/quicklog/diet_parser.py:279`), "삶은 달걀"의 "은"을 조사로 지움.

## 3. 영양제 상담

- 안전 기준(금지 표현, 고위험 주의 문구, 미확인 성분 처리)은 57/57 통과.
- **10/57이 내용 없는 고정 문장**("확보된 로컬 근거 문서만으로 답변합니다…")으로 끝난다. 아연 공복, 운동 전 프로틴, 종합비타민 매일, 임산부 종합비타민처럼 흔한 질문도 포함.
  - 원인: LLM이 `WEB_SEARCH_REQUIRED`를 내면 웹 검색 조건(`not final_docs`)이 BM25가 항상 문서를 돌려줘서 성립하지 않고, 대신 고정 문장으로 바꾼다(`engines/supplement/supplement_engine.py:773, 792`). 이 문장은 "약한 답변" 판정에 걸리지 않아 근거 문서 기반 재답변도 안 탄다.
- 지식 베이스가 좁다: 멜라토닌·테아닌 등은 "자료에 없음". 근육량 증가 추천에 크레아틴만 나오고 단백질은 빠짐.
- 문장 이어붙이기 흔적: "확인하시는 것이 개인 상태에 따라 달라질 수 있습니다", 같은 상담 권고가 답변·주의에 2~3번 반복.
- 성분 인식이 부분 문자열이라 "500mg"의 Mg를 마그네슘, "caffeine"의 Fe·Ca를 철·칼슘, "수술"의 "술"을 알코올로 오인할 수 있다(`engines/supplement/query_understanding.py`).
- 응답 20~43초. 화면에서 기다리기엔 길다.

## 4. 운동+식단 기록 (`/parse-log`)
- 8/8 정확(lbs 환산, "데드 140 5개 3셋", "5x5", 피라미드 3세트 분리 포함). 1~2초.
- FE는 이 엔드포인트를 호출하지 않는다(백엔드 프록시만 있음). 폴백 경로에서 "프로틴 30g"이 3600kcal로 계산되는 버그가 코드에 있다(`engines/quicklog/nlp_engine.py:229-238`).

## 5. 음성 인식 (코드 검토만)
- Whisper `small` int8 CPU, 도메인 단어 힌트(`initial_prompt`)와 무음 제거(`vad_filter`) 없음. `async` 핸들러 안에서 동기 변환이라 변환 중 다른 요청이 막힌다.

## 개선 우선순위

| 순위 | 작업 | 기대 효과 | 규모 |
|---|---|---|---|
| 1 | `custom` 분할이면 `targetMuscles` 사용 | 부위 직접 선택 루틴 복구 | 작음 |
| 2 | 음식 재정렬의 부분 문자열 매칭 제거(짧은 이름이 긴 이름 안에 들어가는 경우만 허용), "개·조각·캔·그릇" 단위 표 확장, 모르는 단위는 1인분 기준 | 칼로리 큰 오류 제거 | 중간 |
| 3 | 중량: 본인 기준 → 같은 운동 기록 → 차용 순서, 차용 시 장비·동작 비율(덤벨 한 손 약 40%, 고립 0.5), 목표 반복+RIR 기반 공식 | 비현실적 중량 제거 | 중간 |
| 4 | 중복 exerciseId 거부, 분할 내 근육 최소 커버(밀기면 삼두·어깨 1개 이상), 운동당 최소 2세트 | 루틴 구성 균형 | 중간 |
| 5 | 프로필 통증을 후보 필터에 반영, 폴백 루틴도 같은 필터 적용, 폴백 사유 코드·문구 정정 | 허리 통증 사용자 데드리프트 처방 방지 | 작음 |
| 6 | 영양제 `WEB_SEARCH_REQUIRED` 시 근거 문서 기반 재답변, 성분 인식 단어 경계 처리 | 상투 답변 18% → 감소 | 작음 |
| 7 | 설명문을 최종 처방 확정 뒤 생성하거나 최종 수치를 넣어 다듬기 | 설명 깊이 | 중간 |
| 8 | 평가 세트 보강: 이번 추가 케이스(콜라·라면·샐러드, custom 분할, 중량 상식 검사)를 회귀 세트로 | 재발 방지 | 작음 |
