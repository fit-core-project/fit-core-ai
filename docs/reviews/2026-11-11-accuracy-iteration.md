### 이번 라운드에 들어간 일반 규칙
- 영양제: LLM 파싱 폴백(규칙 파서가 성분/의도를 못 찾을 때 KB 어휘로만 매핑, 규칙 결과에 병합), 자모 단위 오타 매칭, 구어 맥락(임테기·모유·면역억제제·아이), 약 이름 일반 감지("○○약"), LLM 거부 시 정직성 안내, 질환·주제(보관·원료) 미수록 안내, 위험 맥락 상담 문구 보장, 용량 숫자 제거, 마크다운 제거·번호 재정렬.
- 식단(수식화): LLM은 이름·수량·단위·끼니만 사용. kcal = DB/제품/큐레이션 밀도 × 결정론적 그램(명시 무게 → 음식별 단위표 → 머리명사 단위표 → 1회분 접미사표 → 제품 포장 → 일반 기본값). DB 행이 없으면 머리명사 범주 중앙값 밀도(같은 기준 단위, 5행 이상). LLM 매크로는 최후 수단. LLM 기반 분량 보정 제거, 낱개 중량표(떡·빵·과자·통닭), 정식 분리, 세트 메뉴 확장, 반반 치킨, 남김·나눠줌·분수, 말 정정, 단위 오타.
- 시도 후 되돌린 것: MFDS 음식 DB '식품중량'을 1회분으로 사용(포장/1회분이 섞여 모든 dev 세트 하락), LLM 이름 결정론 보정(정상 정규화까지 덮어써 v4 −16).

1. 식단 A 버킷(약 55~60%): gemma4(8B 로컬)가 단문·음성·오타 문체와 분량 추정에서 반복 실패. 로컬 유지 결정이라 모델 교체 없이 남은 레버는 (a) 추출 전용 프롬프트·few-shot 정비(캐시 무효 → 별도 측정 필요), (b) 결정론 파서를 1차, LLM을 보조로 바꾸는 구조 전환.

- **LLM 매크로 타당성 검사** (`diet_parser.py`): DB 미스 후 LLM 매크로가 0이거나 100 g당 15 kcal 미만이면(물·블랙커피·제로음료·차 등 실제 0 kcal 음식은 예외 목록) 비정상으로 보고 결정론 그램 × 범주 밀도(이름이 가리키는 가공식품 계열의 라벨 중앙값 → 없으면 음료 기본 밀도)로 대체한다. 대체할 밀도·그램이 없으면 LLM 값이 그대로 남는다(blind v6 `dh6_040` "Cheetos 1봉" 0 kcal이 이 경로). 음료 100 ml당 150 kcal 초과도 비정상으로 본다. 비상식적 분량(3 kg 초과)은 오독으로 처리.
- **매칭된 DB 행의 음식 범주로 분량 결정** (`food_units.py` `category_portion_grams`): 밥류 `공기`, 반찬 `접시`/양 미기재(나물 50·김치 51·생채/무침 70·조림 80 g — MFDS 음식 DB '식품중량'의 급식/가정식 행 범주 중앙값, 프랜차이즈·정확히 100 g 자리표시값 제외), 전 `장`/`개`, 찜 가정식 1회분, 돈가스 `장` 130 g, 생선 `마리`(가식부), 냄비(탕·전골·찌개는 4인분, 그 외는 1인분). 음식별 '식품중량'은 여전히 쓰지 않는다(포장·급식·1회분 혼재).
- **검색 측**: MFDS 어순 재배열 일치(고구마돈가스 = "돈가스 고구마") 우선, 수식어만 이름으로 가진 후보 배제(두부면 ≠ 두부), 말린 원재료 대신 조리된 형제 행, 제품 계열 밀도(사분위 창), 라벨 1회분 0·100 g 자리표시 무시 (`food_engine.py`, `food_reranker.py`, `food_canonical_index.py`, `curated_products.py`).
- **영어 음식명 결정론 번역** (`food_query_normalization.py`): 머리-끝 합성(zucchini jeon → 애호박전, braised lotus root → 연근조림), 단어별 합성이 안 되는 구는 사전(rice cake → 떡), 모르는 단어가 있으면 번역하지 않고 검색에 맡김.
- 평가 하네스: `diet_stage_eval.py` 검색 래퍼가 새 키워드 인자(`small_portion`)를 통과시키도록 수정. 신규 테스트 `tests/test_diet_fallback_rules.py`, `tests/test_food_portion_rules.py`.
