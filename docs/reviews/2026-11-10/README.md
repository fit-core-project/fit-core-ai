# AI 단계별 진단 평가 및 원인별 수정 (2026-11-09~10, Claude Code)

`2026-11-08` 리뷰는 케이스가 적고(식단 12, 루틴 11) 걸린 케이스만 고치는 방식이어서 한계가 있었습니다. 이번에는 다음 순서로 진행했습니다.

1. 기존 평가셋의 타당성을 검토했습니다.
2. 실사용 입력 기준으로 평가셋을 새로 만들었습니다. 각 케이스는 단계별 정답을 갖고 있고, 개발용(dev)과 검증용(test)으로 나뉩니다.
3. 실제 LLM(gemma4)으로 측정하면서 원시 출력을 캐시했습니다.
4. 오류를 **처음 실패한 단계**와 원인으로 분류했습니다.
5. 원인 단위로 고친 뒤, 같은 LLM 출력(캐시)으로 다시 측정했습니다.

## 4. 원인별 수정 내역

### 루틴
- **후보 풀 쏠림:** 상위 12개 후보가 큰 근육(가슴 등)으로만 채워졌습니다. 이제 목표 근육마다 2자리를 보장합니다 (`candidate_ranker._select_diverse_pool`).
- **트림 순서 통일:** 세트 예산, 시간 예산, 세트 상한 세 곳을 같은 규칙으로 맞췄습니다. 2세트까지 줄인 뒤 중복 근육 운동을 먼저 빼고, 마지막에만 1세트를 허용합니다 (`prescription/trim.py`).
- **커버리지 교체 시 DOMS 상한 재적용:** 교체해 넣은 운동에도 DOMS 세트 제한을 다시 적용합니다.
- **남은 시간 채우기:**
  - 아직 안 들어간 목표 근육과 덜 쓴 근육부터 채우고, 추가할 때마다 다시 계산합니다.
  - DOMS 2인 근육은 최대 2세트까지 허용합니다.
  - 컨디션이 낮은 날은 채우지 않습니다.
- **후보 0개면 LLM 호출 생략:** 바로 `failed/emptyCandidate`를 반환합니다.
- **여러 장비가 적힌 기록의 무게 차용:** 목표 운동의 장비가 기록의 장비 목록에 있으면 같은 장비로 했다고 봅니다. 덤벨 컬이 5kg으로 나오던 문제를 고쳤습니다.
- **fallback 제목:** custom 분할의 제목을 "맞춤형"으로 표시합니다.

### 식단
- **매칭 필터 오차단:** 한국어 합성어의 머리말 규칙을 반영했습니다. 밥 → 쌀밥, 삼겹살 → 삼겹살구이, 와퍼, 불고기버거가 이제 매칭됩니다 (`food_reranker._token_match_is_plausible`).
- **일반명의 가공품 매칭:** 이름만 있는 일반명에는 착즙·주스 같은 가공 형태보다 기본 행을 우선합니다 (`_plainness_score`).
- **어휘 연관 없는 매칭 거부:** 맥주 → 맥치킨 버거, 소주 → 소금처럼 어휘 연관 없이 임베딩만 가까운 매칭은, 유사도 0.9 미만이면 거부합니다 (`has_lexical_relation`, `LEXICAL_GUARD_SIMILARITY`).
- **구어체 별칭 추가:** 공기밥, 햇반, 아아, 라떼, 카레, coke, pho, 돈까스 등.
- **1인분 기준 도입:**
  - 수량이 없으면 100g 대신 1인분으로 계산합니다.
  - 그릇·인분·접시·개 단위는 음식별 1인분 무게를 씁니다 (`food_units.serving_grams`, `SERVING_GRAMS_BY_SUFFIX`).
  - 작은 품목은 개당 무게를 따로 둡니다 (초밥, 마카롱, 아몬드 등).
- **LLM의 100g 자리채움 처리:** 입력에 수량이 없는데 LLM이 100g을 채우면 수량 없음으로 되돌립니다.
- **주류 열량:** 알코올 열량은 단백질·탄수화물·지방으로 표현되지 않아 0kcal로 기록됐습니다. 라벨 기준 kcal를 명시했습니다.
- **결정론 파서:**
  - 한글 수사를 인식합니다 (한 공기, 두 조각, 반 팩, 1/3공기, 열댓 개, 한 마리 반, 하나).
  - 단위 뒤 조사를 허용합니다.
- **LLM 단위 문자열 분리:** "한 컵", "반공기", "30cm"처럼 단위에 섞인 수량을 분리합니다.
- **음식 아닌 입력 차단:** LLM이 빈 결과를 낸 경우 결정론 fallback 항목은 DB나 식품표에 매칭될 때만 남깁니다.
- **LLM 실패 경로 보강:** LLM이 실패해도 DB와 식품표로 영양값을 채웁니다.

### 영양제
- **큐레이션 KB 직접 로드:** 벡터 인덱스가 낡아 성분 프로필 10개 중 5개(아연, 프로틴, 종합비타민, 실리마린, 유산균)가 빠져 있었습니다. 서버 시작 시 JSON에서 직접 읽습니다 (`supplement/kb_documents.py`).
- **성분 별칭 추가:** 비타민디, 피쉬오일, 종합 비타민(띄어쓰기), 프로바이오틱, 프로테인 등.
- **의도 키워드 보정:**
  - 시기 키워드: 빈속, 운동 직후, 아침에 등.
  - 증상 키워드: 메스꺼, 비린, 더부룩 등.
  - "계속 먹어도"를 증상이 아니라 장기 복용으로 분류합니다.
  - 성분과 함께 쓰인 "도움"을 추천 요청이 아니라 효능 질문으로 분류합니다.
- **상담 안내 누락:** KB 밖 성분과 약을 같이 묻는 질문에도 상담 안내를 붙입니다.
- **문서 매칭:** 주의 문서 관련성을 단어 경계로 매칭합니다.

### 공통
- **GPU 경합으로 인한 멈춤:** 8GB GPU에서 임베딩 모델과 gemma4를 같이 올리면 Ollama가 밀려나 요청이 수 분간 멈췄습니다. `AI_EMBEDDING_DEVICE=cpu` 설정을 추가했습니다 (`.env.example`).
